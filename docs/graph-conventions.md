# Graph input and output conventions

Phase 7 is authorized after the owner's Phase 6 approval. All fifteen topics retain their canonical Graph paths. These conventions describe validation and representation; each lesson states its own graph assumptions.

Vertices are integers 0 through V-1. Python rejects bool as an integer, nonintegral values and invalid endpoints. General limits are 0<=V<=1000 and 0<=E<=10000. Floyd-Warshall and Johnson limit V to 100. Inputs are edge sequences, unweighted pairs (u,v) or weighted triples (u,v,w). Adjacency lists preserve input edge order. Undirected edges create two arcs with the same original input-position edge ID, including self-loops. Duplicate and parallel edges remain distinct. Isolated vertices and disconnected graphs are retained. No algorithm mutates the caller's edge sequence.

Python APIs use a bool directed flag where appropriate. Topological sorting, SCC and Johnson require directed mode; MST, Union-Find, bridges and articulation points require undirected mode. BFS, DFS and single-source shortest paths support both. API source=None is valid only for an empty graph; a nonempty graph requires a valid source. Traversals are deterministic: input adjacency order, ascending forest roots, and explicit heap ties stated in lessons. DFS component labels denote its forest roots, not strongly connected components.

Unreachable distances are None in Python and null in JSON. Negative-cycle-affected distances are the string "-inf". Affected paths have no finite predecessor path. Parent and parent_edge entries are None/null at roots, unreachable vertices and affected vertices. Path reconstruction returns both original edge IDs and vertices, distinguishing parallel edges. A finite path is reconstructed by following parents and reversing. Ties retain first strict improvement; BFS retains first discovery. MST outputs original edge IDs and a total forest weight.

Weights are integers in [-10^6,10^6], except Dijkstra supports [0,10^12]; A* supports [0,10^6]. Zero weights are valid. Python arbitrary precision and C++ signed integers with at least 63 value bits produce identical finite values within these contracts. Dijkstra simple paths are at most 999*10^12. Bellman-Ford's in-place relaxation intermediates are bounded by V*2E*10^6 (undirected reverse arcs included), safely below 64-bit limits. Floyd uses an internal -10^12 clamp, below any finite simple-path value (99*10^6), and then labels all pairs reachable through a negative cycle; unreachable infinity is never added. Johnson potentials and reweighting use the stated bounded signed arithmetic. C++ uses separate unreachable/negative sentinels of +/-4*10^18 that cannot collide with finite results. Input bounds are checked before graph allocation.

Python executable input is one JSON object with named API arguments; output is JSON. C++ executable input is whitespace-delimited integers: V E directed (0 or 1), then source if required; A* then goal and V heuristic values; finally E edge records. Source/goal -1 means absent for V=0. C++ accepts strict signed decimal tokens (no leading plus), rejects missing/trailing tokens and exits 2 on invalid input with an error on stderr; Python exits 2 for invalid arguments. Both produce one JSON result on success. See per-lesson examples. All C++ solution files support ALGORITHM_ATLAS_NO_MAIN for API tests/reuse.

A* heuristics are integers in [0,10^9], one per vertex, with h(goal)=0. Admissibility is a caller guarantee needed for optimal early-goal termination; consistency is sufficient but not required because improvements reopen vertices. Arbitrary overestimates can return a suboptimal path. Negative edges are rejected. Bellman-Ford marks only vertices reachable from a source-reachable negative cycle. Floyd marks each affected source-target pair. Johnson rejects any negative cycle, including one disconnected from other vertices, by connecting a super-source to every vertex.
